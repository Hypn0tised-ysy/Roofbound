# Roofbound 数据库操作指南

本文说明如何在**现有 SQLite 架构**上扩展更多数据读写，无需重写底层。当前已实现：**通关时写入 `RUN_RECORD`、查询最短通关时间并在胜利界面显示**。

---

## 1. 架构总览

项目采用经典三层结构：

```
┌─────────────────────────────────────────────────────────┐
│  UI / 游戏逻辑（LevelComplete、UIManager、levelController）│
└───────────────────────────┬─────────────────────────────┘
                            │ 调用
┌───────────────────────────▼─────────────────────────────┐
│  Service 层（业务封装，推荐新增逻辑写在这里）              │
│  例：BestTimeService、PlayerSession                       │
└───────────────────────────┬─────────────────────────────┘
                            │ 调用
┌───────────────────────────▼─────────────────────────────┐
│  DAO 层（按表封装 SQL）                                   │
│  PlayerAccountDAO / LevelInfoDAO / RunRecordDAO           │
└───────────────────────────┬─────────────────────────────┘
                            │ 调用
┌───────────────────────────▼─────────────────────────────┐
│  DatabaseManager（单例，连接 + ExecuteQuery/NonQuery）    │
└───────────────────────────┬─────────────────────────────┘
                            │
                    game_data.db（SQLite 文件）
```

**设计原则：**

- **UI 脚本不要直接写 SQL**，优先调用 `*DAO` 或 `*Service`。
- **跨表、带业务规则**的逻辑放在 `*Service`（参考 `BestTimeService`）。
- **单表 CRUD** 放在 `*DAO`（参考 `RunRecordDAO`）。
- 任何数据库操作前，确保已触发 `DatabaseManager.Instance`（会自动创建并 `DontDestroyOnLoad`）。

## 3. 数据表结构

### PLAYER_ACCOUNT（玩家账户）

| 字段 | 类型 | 说明 |
|------|------|------|
| Player_ID | VARCHAR(36) PK | GUID |
| Username | VARCHAR(50) UNIQUE | 用户名 |
| Creation_Date | DATETIME | 创建时间 |
| Total_Play_Time | INT | 累计游戏时长（秒） |
| Total_Deaths | INT | 累计死亡次数 |
| Points | INT | 积分 |

### LEVEL_INFO（关卡配置）

| 字段 | 类型 | 说明 |
|------|------|------|
| Level_ID | INTEGER PK | 自增，1 起 |
| Level_Name | VARCHAR(100) | 关卡名 |
| Difficulty | INT | 难度 |
| Target_Time_3Star | FLOAT | 三星目标时间（秒） |
| Target_Time_2Star | FLOAT | 二星目标时间（秒） |

首次建库会自动插入：`Level01`、`Level02`、`Level03`（各一条）。

### RUN_RECORD（通关流水，可多条）

| 字段 | 类型 | 说明 |
|------|------|------|
| Record_ID | VARCHAR(36) PK | GUID |
| Player_ID | FK | 玩家 |
| Level_ID | FK | 关卡 |
| Completion_Time | FLOAT | 本次用时（秒） |
| Earned_Stars | INT | 星级 |
| Record_Date | DATETIME | 记录时间 |

**最短通关时间** = 同一 `Player_ID + Level_ID` 下 `Completion_Time` 的最小值（见 `RunRecordDAO.GetPlayerBestRecord`）。

## 4. 关卡 ID 与 UIManager 的对应

`UIManager.SelectedLevelIndex` 为 **0 起**（选关按钮 index），数据库 `Level_ID` 为 **1 起**：

| SelectedLevelIndex | 场景（示例） | Level_ID |
|--------------------|--------------|----------|
| 0 | Level01 | 1 |
| 1 | Level02 | 2 |
| 2 | Level03 | 3 |

转换代码（已在 `BestTimeService.ResolveLevelId`）：

```csharp
int levelId = levelIndex + 1;
```

新增关卡时：在 `LEVEL_INFO` 插入对应行，并保证 `UIManager.levelSceneNames` 顺序与 `Level_ID` 一致。

## 5. 本地玩家会话

单机默认玩家由 `PlayerSession.GetOrCreateLocalPlayerId()` 管理：

1. 读 `PlayerPrefs` 中的 `LocalPlayerId`
2. 若无或数据库中不存在 → 创建 `Username = "Player"` 并保存 ID

**几乎所有「按玩家统计」的操作都应先取玩家 ID：**

```csharp
string playerId = PlayerSession.GetOrCreateLocalPlayerId();
if (string.IsNullOrEmpty(playerId)) return;
_ = DatabaseManager.Instance; // 确保数据库已初始化
```

## 7. 现有集成点（可挂更多逻辑）

### 胜利 → 写库 + 显示

`LevelComplete.OnEnable()`：

```csharp
float finalTime = UIManager.Instance.GetRunTime();
int levelIndex = UIManager.Instance.SelectedLevelIndex;
float bestTime = BestTimeService.SaveCompletionAndGetBest(levelIndex, finalTime);
```

扩展胜利界面时，在此读取 DAO 数据刷新 UI 即可。

### 死亡 → 可记录死亡次数

在 `UIManager.TriggerGameOver()` 或 `levelController.TriggerGameDead()` 中增加：

```csharp
string playerId = PlayerSession.GetOrCreateLocalPlayerId();
if (!string.IsNullOrEmpty(playerId))
{
    _ = DatabaseManager.Instance;
    PlayerAccountDAO.AddDeathCount(playerId);
}
```

### 关卡选择 → 可显示每关 Best Time

在 `LevelSelect` 刷新按钮时：

```csharp
if (BestTimeService.TryGetBestTime(levelIndex, out float best))
    label.text = Panel_HUD.FormatTime(best);
else
    label.text = "--:--.--";
```

## 8. 如何新增一种数据库操作（推荐步骤）

以「查询玩家总积分并在主菜单显示」为例。

### 步骤 1：确认 DAO 是否已有方法

`PlayerAccountDAO.GetPlayerByID` 已返回 `Points`，通常**不必改 DAO**。

### 步骤 2：新建 Service（可选但推荐）

`Assets/Scripts/database/PlayerStatsService.cs`：

```csharp
public static class PlayerStatsService
{
    public static int GetLocalPlayerPoints()
    {
        string playerId = PlayerSession.GetOrCreateLocalPlayerId();
        if (string.IsNullOrEmpty(playerId)) return 0;

        _ = DatabaseManager.Instance;
        PlayerAccount account = PlayerAccountDAO.GetPlayerByID(playerId);
        return account?.Points ?? 0;
    }
}
```

### 步骤 3：在 UI 中调用

```csharp
pointsText.text = PlayerStatsService.GetLocalPlayerPoints().ToString();
```

### 步骤 4：在 Unity 中验证

Play → 通关一次 → 看 Console 是否有「记录成绩成功」→ 主菜单读积分是否增加。

## 9. 如何新增一张表

### 步骤 1：在 `DatabaseManager.CreateTables()` 增加建表 SQL

```csharp
string createAchievementTable = @"
    CREATE TABLE IF NOT EXISTS ACHIEVEMENT (
        Achievement_ID INTEGER PRIMARY KEY AUTOINCREMENT,
        Player_ID VARCHAR(36) NOT NULL,
        Code VARCHAR(50) NOT NULL,
        Unlocked_Date DATETIME NOT NULL,
        UNIQUE(Player_ID, Code)
    )";
ExecuteNonQuery(createAchievementTable);
```

> 注意：已发布的旧库不会自动有新表，除非用户删库或你写**迁移脚本**（见第 11 节）。

### 步骤 2：新建模型 + DAO 文件

`Achievement.cs`：

```csharp
[Serializable]
public class Achievement
{
    public int Achievement_ID { get; set; }
    public string Player_ID { get; set; }
    public string Code { get; set; }
    public DateTime Unlocked_Date { get; set; }
}

public static class AchievementDAO
{
    public static bool Unlock(string playerId, string code)
    {
        try
        {
            string query = @"INSERT OR IGNORE INTO ACHIEVEMENT
                (Player_ID, Code, Unlocked_Date)
                VALUES (@Player_ID, @Code, @Unlocked_Date)";
            SqliteParameter[] parameters = {
                new SqliteParameter("@Player_ID", playerId),
                new SqliteParameter("@Code", code),
                new SqliteParameter("@Unlocked_Date", DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss"))
            };
            DatabaseManager.Instance.ExecuteNonQuery(query, parameters);
            return true;
        }
        catch (Exception e)
        {
            Debug.LogError($"解锁成就失败: {e.Message}");
            return false;
        }
    }
}
```

### 步骤 3：Service + 游戏事件触发

```csharp
// 首次三星通关
if (stars >= 3)
    AchievementDAO.Unlock(playerId, "level_" + levelId + "_3star");
```

## 10. 在 DAO 中新增查询（模板）

在对应 `*DAO` 类中追加静态方法，**务必使用参数化查询**防 SQL 注入：

```csharp
public static int GetClearCount(string playerId, int levelId)
{
    try
    {
        string query = @"SELECT COUNT(*) FROM RUN_RECORD
                         WHERE Player_ID = @Player_ID AND Level_ID = @Level_ID";
        SqliteParameter[] parameters = {
            new SqliteParameter("@Player_ID", playerId),
            new SqliteParameter("@Level_ID", levelId)
        };
        DataTable result = DatabaseManager.Instance.ExecuteQuery(query, parameters);
        return Convert.ToInt32(result.Rows[0][0]);
    }
    catch (Exception e)
    {
        Debug.LogError($"查询通关次数失败: {e.Message}");
        return 0;
    }
}
```

读取多行时参考 `RunRecordDAO.GetPlayerRecords` 的 `foreach (DataRow row in result.Rows)` 模式。

### A. 关卡排行榜 UI

List<RunRecord> top = RunRecordDAO.GetTopPlayersByLevel(levelId, limit: 10);
foreach (RunRecord r in top)

### B. 历史成绩列表

```csharp
string playerId = PlayerSession.GetOrCreateLocalPlayerId();
List<RunRecord> history = RunRecordDAO.GetPlayerRecords(playerId);
// 按 Record_Date 降序，已在 DAO 中 ORDER BY
```

### C. 只更新最短记录、不每次 INSERT

当前设计是**流水表**（每次通关一条），最短时间靠 `MIN(Completion_Time)` 查询。若希望只保留一条最佳记录，可新增 `UpdateBestIfBetter` 方法，或增加 `PLAYER_LEVEL_BEST` 汇总表；一般流水表更利于做统计和排行榜。

### D. 同步关卡配置与 Build Settings

新增 `Level04` 时：

1. `LevelInfoDAO.AddLevel(new LevelInfo { Level_Name = "Level04", ... })`
2. `UIManager.levelSceneNames` 增加 `"Level04"`
3. Build Settings 加入场景

## 12. 数据库迁移与调试

### 重置数据库

删除 `persistentDataPath` 下的 `game_data.db`，下次运行会重建表并插入默认三关。

### 修改表结构（已上线存档）

`CREATE TABLE IF NOT EXISTS` **不会**修改已有表。可选做法：

1. 增加 `DatabaseManager` 的 `schema_version` 表 + 按版本执行 `ALTER TABLE`
2. 或 bump 文件名如 `game_data_v2.db`

简单项目开发阶段可直接删库。

### 查看 Log

成功初始化：`数据库初始化成功，路径：...`  
写入成绩：`记录成绩成功！获得X星，增加Y积分`

### 依赖

使用 `Mono.Data.Sqlite`（Unity 需启用相应程序集；若编译报错，在 Player Settings → Api Compatibility Level / 程序集定义中确认 SQLite 可用）。

## 14. 小结

1. **先** `DatabaseManager.Instance` + `PlayerSession.GetOrCreateLocalPlayerId()`  
2. **优先**用现有 DAO；复杂逻辑加 `*Service`  
3. **关卡索引**记得 `levelIndex + 1` → `Level_ID`  
4. **UI 层**只调 Service，保持 SQL 集中在 `database` 目录  
5. **最短通关**已实现：`BestTimeService` + `LevelComplete`，可作为其他功能的参考模板  

按上述模式扩展，即可在不大改现有架构的情况下持续增加数据库功能。
